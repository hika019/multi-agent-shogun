# cmd作成プリフライトチェック（全cmd共通）
# 将軍はcmdを書く前に必ずこのファイルをReadせよ。読まずに書くな。

## 1. cmd作成前

### 過去の教訓を参照したか？
- [ ] このプロジェクト/領域に関連するMCPメモリを確認したか？
- [ ] 同種の過去cmdで殿から指摘・叱責を受けた点はないか？
- [ ] 専用テンプレがあれば読んだか？（例: templates/keiba_cmd.md）

### 範囲を狭めていないか？
- [ ] 殿が「広く調べろ」と言っているのに、実行可能性を気にして絞っていないか？
- [ ] 調査対象を網羅しているか？（一部を調べずに切り捨てていないか）
- [ ] 「調べた上で判断できないから外す」と「調べずに外す」は全く別物

### acceptance_criteriaは具体的か？
- [ ] 全ての基準がテスト可能か？（曖昧な表現はないか）
- [ ] 過去の教訓が基準に組み込まれているか？（MEMORYに書くだけでは不十分）
- [ ] solver系: clippy 0 + compiler warning 0 + git statusクリーン

## 2. 殿に見せたか？（interpret_and_think）

- [ ] 意図・前提・不明点を殿に提示したか？
- [ ] 殿のGoを得てから家老に出したか？
- [ ] YAMLを書く前に考えたか？（考える前にYAMLを書くな）
- [ ] 問題対応の場合: 根本原因は何か？同構造の問題は他にないか？パッチか根本修正か？

## 3. レポート受領時の検品（殿に見せる前）

- [ ] cmdのacceptance_criteriaを全て満たしているか？
- [ ] 「触れていない」部分はないか？（触れないからこそ問い質せ）
- [ ] 調査系: 対象範囲が網羅されているか？（一部が欠落していないか）
- [ ] 数字の意味を理解したか？（数字の横流し禁止）
- [ ] 将軍としての所見・懸念を添えて殿に報告できるか？

## 4. 退行チェック（次のcmdを出す前）

- [ ] 前のcmdに退行（ベンチ数字の悪化）はないか？
- [ ] 退行がある場合、原因は特定されているか？
- [ ] 原因不明の退行がある状態で次の実装cmdを出そうとしていないか？
- [ ] → 原因不明なら調査cmdを先に出せ。実装を重ねると切り分け不能になる
